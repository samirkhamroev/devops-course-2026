# Конфигурация виртуальной машины devops-vm

## 1. Параметры машины
- **Гипервизор:** Oracle VM VirtualBox 7.x
- **Операционная система:** Ubuntu Server 24.04 LTS (64-bit)
- **Имя виртуальной машины:** `devops-vm`
- **Количество ядер процессора (vCPU):** 2
- **Объём оперативной памяти (RAM):** 2048 МБ
- **Объём дискового накопителя:** 25 ГБ (динамически расширяемый VDI)

## 2. Сетевые интерфейсы
- **Сетевой адаптер 1:** NAT (сегмент `10.0.2.0/24`, IP гостя `10.0.2.15/24`). Назначение: доступ виртуальной машины в Интернет к репозиториям пакетов.
- **Сетевой адаптер 2:** Виртуальный адаптер хоста (Host-only, `VirtualBox Host-Only Ethernet Adapter`, сегмент `192.168.56.0/24`, IP гостя `192.168.56.101/24`). Назначение: прямое устойчивое сетевое взаимодействие между хостовой ОС и гостевой ВМ (обращение к веб-ресурсам из браузера).

## 3. Правило проброса портов
- **Наименование правила:** `ssh`
- **Протокол:** TCP
- **Адрес хостовой системы:** `127.0.0.1`
- **Порт хостовой системы:** `2222`
- **Адрес гостевой системы:** не заполняется
- **Порт гостевой системы:** изначально `22`, после выполнения процедуры SSH hardening изменён на `2222`.

## 4. Учётные записи
- **Учётная запись `student`:** системный пользователь первичной установки. Входит в группу `sudo`. Аутентификация по паролю (на начальном этапе) / локальный вход в консоль.
- **Учётная запись `devops`:** сервисно-административная учётная запись для деплоя и управления. Входит в группы `devops`, `sudo`, `docker`. Аутентификация исключительно по открытому ключу SSH (`ed25519`). Парольная аутентификация заблокирована.

## 5. Служба SSH
- **Порт:** `2222`
- **Файлы конфигурации:** `/etc/ssh/sshd_config.d/99-hardening.conf`
- **Параметры безопасности (Hardening):**
  - `Port 2222`
  - `PermitRootLogin no` (запрет входа суперпользователя)
  - `PasswordAuthentication no` (отключение паролей)
  - `PubkeyAuthentication yes` (вход только по SSH-ключам)
  - `PermitEmptyPasswords no`
  - `MaxAuthTries 3` (лимит неудачных попыток аутентификации)
  - `LoginGraceTime 30`
  - `AllowUsers devops` (белый список допущенных пользователей)
  - `X11Forwarding no`
  - `ClientAliveInterval 300`
  - `ClientAliveCountMax 2`
- **Особенности systemd в Ubuntu 24.04:** юнит `ssh.socket` отключён (`systemctl disable --now ssh.socket`), активирован стандартный сервис `ssh.service` (`systemctl enable --now ssh.service`), чтобы директива `Port 2222` имела приоритет.
- **Права на ключевой материал:** `~/.ssh` — `700`, `~/.ssh/authorized_keys` — `600`.

## 6. Правила межсетевого экрана (UFW)
- **Политики по умолчанию:**
  - `default deny incoming` (запрет всех входящих соединений)
  - `default allow outgoing` (разрешение исходящих соединений)
- **Разрешающие правила:**
  - `2222/tcp LIMIT` — управляющий доступ SSH с ограничением частоты подключений (не более 6 соединений за 30 секунд).
  - `80/tcp ALLOW` — входящий веб-трафик HTTP (для редиректа на HTTPS).
  - `443/tcp ALLOW` — входящий защищённый трафик HTTPS.

## 7. Снимки состояния
1. **`01-clean-install`** — создан сразу после завершения чистой установки ОС и обновления пакетов (`apt update && apt upgrade`). Точка полного сброса.
2. **`02-keys-configured`** — создан после заведения пользователя `devops`, настройки SSH-ключей и проверки подключения по алиасу `ssh devops`.
3. **`03-ssh-hardened`** — создан после переноса SSH на порт 2222, отключения root/паролей и включения межсетевого экрана UFW.
4. **`04-nginx-https`** — создан после установки Nginx, генерации SAN-сертификата и настройки защищённого сайта по HTTPS с редиректом.
5. **`05-docker-compose`** — создан после развёртывания контейнеризированного приложения Flask + PostgreSQL с томами данных.

## 8. Веб-сервер
- **Устанавливаемый пакет:** `nginx`
- **Путь к конфигурации ресурса:** `/etc/nginx/sites-available/devops-site` (активирован через symlink в `/etc/nginx/sites-enabled/devops-site`, дефолтный хост `default` удалён).
- **Каталог ресурса:** `/var/www/devops-site`
  - Владелец: `devops:devops`
  - Права: `755` для каталогов, `644` для файлов (модель «владелец пишет, веб-сервер www-data читает»).
- **Пути к SSL-сертификату и закрытому ключу:**
  - Сертификат: `/etc/ssl/certs/devops.crt` (права `644`, владелец `root`).
  - Закрытый ключ: `/etc/ssl/private/devops.key` (права `600`, владелец `root`).
- **Срок действия сертификата:** 365 дней, расширение `Subject Alternative Name: DNS:devops.local`.
- **Команда генерации сертификата:**
  ```bash
  sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
    -keyout /etc/ssl/private/devops.key \
    -out /etc/ssl/certs/devops.crt \
    -subj "/CN=devops.local" \
    -addext "subjectAltName=DNS:devops.local"
  ```

## 9. Контейнеризация
- **Способ установки Docker Engine:** официальный apt-репозиторий Docker (пакеты `docker-ce`, `docker-ce-cli`, `containerd.io`, `docker-buildx-plugin`, `docker-compose-plugin`).
- **Участники группы docker:** пользователь `devops`.
- **Расположение проекта на сервере:** `~/app` (`/home/devops/app`).
- **Файл переменных окружения:** `~/app/.env` (права `600`, исключён из git и `.dockerignore`).
- **Публикуемые порты:**
  - Приложение: `127.0.0.1:5000:5000` (привязка строго к localhost для предотвращения прямого доступа извне в обход межсетевого экрана).
  - СУБД PostgreSQL: порт `5432` не публикуется наружу, доступен только внутри Docker-сети `backend`.
- **Именованные тома:** `db_data` для персистентного хранения данных базы PostgreSQL в `/var/lib/postgresql/data`.
- **Конфигурация обратного прокси-сервера (Nginx):**
  - Блок `location /app/` в конфигурации `/etc/nginx/sites-available/devops-site`:
    - `proxy_pass http://127.0.0.1:5000/;`
    - Проброс заголовков `Host`, `X-Real-IP`, `X-Forwarded-For`, `X-Forwarded-Proto`.
